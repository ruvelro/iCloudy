# S3 y servicios compatibles

iCloudy se conecta a Amazon S3 y a los servicios que copian su API: Backblaze B2, Wasabi, Cloudflare R2, Scaleway,
DigitalOcean Spaces, MinIO y cualquier otro servidor compatible (Garage, Ceph RGW…). No usa ningún SDK: cada petición
se firma en el Mac con AWS Signature Version 4, escrita sobre CryptoKit. La clave secreta se guarda en el Llavero y
**nunca viaja**: solo sirve para derivar la firma de cada petición.

El código está en `Sources/iCloudy/Providers/S3/`:

| Archivo | Qué hace |
|---|---|
| `S3Signer.swift` | SigV4: petición canónica, cadena a firmar, clave de firma, cabecera `Authorization` y URL prefirmadas. |
| `S3Location.swift` | Servicios conocidos, regiones, y cómo se construye la dirección (estilo ruta o subdominio). |
| `S3Provider.swift` | Transporte con reintentos, listados, carpetas, búsqueda, enlaces y el contrato `CloudProvider`. |
| `S3Transfers.swift` | Subidas simples y por partes, reanudación, descargas por rangos, copias, movimientos y borrados. |
| `S3XML.swift` | Lectura de las respuestas XML con `XMLParser` y traducción de los errores a mensajes en castellano. |
| `S3Authentication.swift` | Comprobación de las claves al conectar y construcción de la cuenta. |

## Conectar

En «Añade tu nube» → «Almacenamiento de objetos» → «Conectar S3». El formulario pide:

- **Servicio**. Amazon S3, Wasabi, Scaleway y Spaces eligen la región de una lista; Backblaze B2 la escribe (es la
  parte de la dirección S3 del bucket, por ejemplo `eu-central-003`); Cloudflare R2 pide el ID de cuenta y usa la
  región `auto`; «MinIO u otro compatible» pide la dirección completa (`https://minio.ejemplo.com:9000`) y una
  región, `us-east-1` si el servidor no usa regiones.
- **ID de clave de acceso** y **clave secreta**.
- **Bucket (opcional)**. Vacío, la raíz de la cuenta es la lista de buckets que la clave puede listar. Con un nombre,
  la raíz es ese bucket. Una clave limitada a un bucket (las claves de aplicación de B2, por ejemplo) no puede listar
  los demás, y el formulario lo explica si se deja vacío.
- **Avanzado → Direccionamiento**. En automático, los servidores propios y R2 usan el estilo ruta
  (`servidor/bucket/clave`) y el resto el subdominio (`bucket.servidor/clave`), salvo que el nombre del bucket no quepa
  en un nombre de host con TLS (mayúsculas, guiones bajos o puntos): entonces también va por ruta.

Antes de guardar nada, iCloudy lista el bucket (o los buckets) con esas claves. En AWS, si el bucket está en otra
región que la elegida, la respuesta lo dice y la cuenta se conecta a la región correcta sin preguntar.

Una dirección `http://` solo se admite en la red local, como en WebDAV: la clave no viaja, pero los archivos y las
peticiones firmadas irían en claro.

La cuenta se identifica por el servicio, el bucket y el ID de clave (`s3:host/bucket#clave`): la misma clave en dos
buckets, o dos claves en el mismo bucket, son dos cuentas. Volver a conectar con los mismos tres datos sustituye la
clave secreta guardada.

## Carpetas

S3 no tiene carpetas, solo claves con barras. iCloudy las dibuja a partir de los prefijos comunes del listado
(`ListObjectsV2` con delimitador `/`, siguiendo los `continuation-token`) y de los objetos vacíos `nombre/` que crean
las consolas. «Nueva carpeta» crea precisamente uno de esos marcadores.

Una carpeta sin marcador existe mientras tenga algo dentro: si se borra lo último que contiene, desaparece. Es lo que
hace S3, no un fallo.

El identificador de cada elemento es `bucket/clave`; el de una carpeta termina en `/`. iCloudy no crea, renombra,
mueve ni borra buckets: eso se hace en la consola del proveedor.

## Operaciones

| Operación | Cómo |
|---|---|
| Listar | `ListObjectsV2`, página a página. Sin bucket propio, `ListBuckets`. |
| Descargar | `GET`. Por encima de 64 MiB, en rangos (`Range`) fijados con `If-Match` al ETag del primero: un objeto sustituido a mitad de descarga no produce un archivo hecho de dos versiones, y si se corta la conexión solo se repite el trozo. |
| Subir | Hasta 16 MiB, un `PutObject`. Por encima, subida por partes de 8 MiB como mínimo (más si hace falta para no pasar de 10 000 partes). |
| Renombrar, mover | `CopyObject` y después borrar el original. Una carpeta se copia clave a clave, con progreso, y solo cuando todo se ha copiado se borra el origen: un fallo a medias deja el original entero. |
| Copiar | `CopyObject`; por encima de 5 GiB, `UploadPartCopy` por rangos de 512 MiB. |
| Eliminar | Definitivo: S3 no tiene papelera y la confirmación lo advierte. Una carpeta se borra con `DeleteObjects`, de mil en mil claves. |
| Enlace | URL prefirmada, ver más abajo. |
| Buscar | Por prefijo, ver más abajo. |
| Espacio | No disponible: S3 no tiene un límite que consultar, se paga por lo que se guarda. La barra lateral lo dice en lugar de inventar un porcentaje. |

Renombrar o mover sobre un nombre que ya existe se rechaza antes de copiar nada: S3 sobrescribiría el objeto sin
avisar.

## Enlaces temporales

S3 no tiene enlaces públicos propios. Lo que iCloudy ofrece es una **URL prefirmada**: lleva la firma en la propia
dirección y funciona para cualquiera que la tenga hasta que caduca. Al crearla se elige cuánto dura: una hora, un día
o siete días, que es el máximo que permite SigV4. El diálogo y el mensaje la llaman «enlace temporal» y dicen hasta
cuándo vale.

No se puede revocar antes de que caduque salvo desactivando la clave de acceso que la firmó. Solo hay enlaces de
archivos, no de carpetas.

## Búsqueda

S3 solo sabe buscar por **prefijo de clave**: el término es el principio de la ruta completa, desde la raíz del
bucket, y distingue mayúsculas. `informes/2024` encuentra `informes/2024/enero.pdf`, pero `enero` no lo encuentra. Sin
bucket propio, la búsqueda recorre los buckets uno tras otro. Los resultados se marcan siempre como incompletos, porque
un nombre en mitad de una ruta no se encuentra así. Para buscar dentro de la carpeta que se está viendo, el filtro de
la carpeta sigue funcionando.

## Integridad

- **Subida simple**: se envía `Content-MD5` y el hash SHA-256 real del cuerpo en `x-amz-content-sha256`, de modo que
  el servidor rechaza un cuerpo que haya cambiado por el camino. El ETag que devuelve es el MD5 de lo guardado y se
  compara con el calculado aquí.
- **Subida por partes**: cada parte lleva su `Content-MD5` y su ETag se compara con el MD5 de esos mismos bytes. Al
  terminar, el ETag del objeto tiene que ser el compuesto que forman las partes: el MD5 de la concatenación de los MD5
  binarios de cada parte, un guion y el número de partes (`md5-de-md5s-N`). Sobre TLS las partes se declaran
  `UNSIGNED-PAYLOAD` (el canal protege el cuerpo y `Content-MD5` lo comprueba); sobre HTTP en la red local se firma su
  hash real.
- **Cifrado con KMS o con clave del cliente**: el ETag deja de ser un MD5. Si la respuesta lo indica, la subida queda
  como «sin suma del proveedor» en lugar de fallar.
- **Descarga**: la verificación común compara el tamaño siempre, y el MD5 cuando el ETag listado es un MD5 simple
  (objeto subido de una vez y no cifrado con KMS). Un ETag con `-N` es de una subida por partes y no describe el
  contenido, así que solo se comprueba el tamaño. Si al descargar la respuesta revela que el objeto está cifrado con
  KMS, su ETag deja de usarse como suma para ese objeto.

## Reanudar y cancelar

Una subida por partes guarda en el checkpoint de la transferencia el `UploadId` y, por cada parte aceptada, su ETag y
el MD5 calculado aquí. Al reanudar:

1. Se pregunta al servidor qué partes tiene (`ListParts`).
2. Se conserva la serie de partes que siguen cuadrando con el archivo: el tamaño esperado y, cuando el ETag es un MD5,
   el MD5 de esos mismos bytes leídos otra vez del disco. Todo lo que sigue a la primera diferencia se vuelve a enviar.
3. Si el servidor ya no conoce la subida (`NoSuchUpload`) pero todas las partes se habían enviado, se mira el objeto:
   si su ETag es el compuesto de esas partes, la subida terminó y solo se perdió la respuesta, y no se repite nada.
   Si no, se empieza una subida nueva.

Cancelar una transferencia llama a `AbortMultipartUpload`, para que las partes no se queden ocupando espacio (y
facturándose) hasta que el servidor las limpie.

## Errores y reintentos

Los errores llegan como XML (`<Error><Code>…`) y se traducen a mensajes con la solución habitual: `AccessDenied`
(permisos de la clave), `NoSuchBucket`, `NoSuchKey`, `SignatureDoesNotMatch` (clave secreta mal copiada o, a menudo,
el reloj del Mac), `RequestTimeTooSkewed`, `InvalidObjectState` (objeto archivado en Glacier), `KeyTooLongError`,
`NotImplemented` (el servicio compatible no admite la operación) y otros. Un código desconocido se muestra tal cual.

- Los 500, 502, 503, 504 y `SlowDown` se repiten con la política común de iCloudy: hasta tres veces, con espera
  creciente o la que pida `Retry-After`, y solo para los métodos que hacen lo mismo dos veces que una (más
  `DeleteObjects`). `CompleteMultipartUpload` y las copias pueden fallar después de responder 200, con el error en el
  cuerpo; también se tratan como fallos.
- Un bucket de otra región de AWS se sigue una vez, firmando para la región que indica la respuesta.
- `RequestTimeTooSkewed` adopta la hora del servidor para esa cuenta y repite la petición una vez.
- `InvalidAccessKeyId` marca la cuenta como caducada: solo una clave nueva lo arregla.

## Límites de esta versión

- No hay papelera, cuota, «Recientes» ni «Compartido conmigo».
- La búsqueda es solo por prefijo.
- No se crean ni se borran buckets.
- No se usan credenciales temporales de STS (token de sesión) ni perfiles de `~/.aws`.
- El progreso de renombrar o mover una carpeta lo informa el proveedor (`relocationProgress`), pero la interfaz todavía
  no lo muestra: la operación aparece como una sola.
- Una subida nueva sobrescribe un objeto con el mismo nombre si existe; la cola de transferencias ya pregunta antes,
  a partir del listado de la carpeta de destino.

## Pruebas

`S3SignerTests` reproduce la batería genérica de SigV4 y los ejemplos de la documentación de S3 (GET con `Range`, PUT
con una clave codificada, subrecurso sin valor, listado y URL prefirmada). `S3ProviderTests` cubre, con respuestas HTTP
simuladas, el direccionamiento, los listados con prefijos y paginación, la subida por partes con reanudación y
cancelación, el ETag compuesto, los objetos con KMS, las descargas por rangos, las copias grandes, los errores y los
reintentos.

`S3IntegrationTests` recorre todo contra un servidor real y se salta si no hay uno. Con Docker y MinIO:

```sh
docker run -d --name minio -p 9000:9000 -e MINIO_ROOT_USER=clave -e MINIO_ROOT_PASSWORD=secreto123 \
  minio/minio server /data
docker exec minio mc alias set local http://127.0.0.1:9000 clave secreto123
docker exec minio mc mb local/pruebas
ICLOUDY_S3_URL=http://clave:secreto123@127.0.0.1:9000/pruebas swift test --filter S3IntegrationTests
```
